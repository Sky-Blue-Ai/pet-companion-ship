# 3D 资产规范与性能预算（G-20 / 21 / 22）

> 与用户提供的《AI 宠物资产预料库 v1.0》的关系：
> - 语料（1200 条）、语音包规则、设计令牌 → **以资料库为准**，已导入 `corpus/` 与 `docs/petlib-v1.md`
> - 美术资产：资料库给的是 **2D 切图规范**（2 品种 × 6 动作 × 3–5 帧），而 v1.0 已定 **3D**（模型 + 骨骼）
> - 所以本文件是 3D 版本的资产规范；2D 切图规范降级为 **UI 图标 / 立绘 / 分享卡** 使用
> - 待确认：宠物本体是否真的用 3D，见文末「待拍板」

美术外包开工前必须先把这份发给对方，否则回来模型用不了。

## 1. 规范（G-20）

| 项 | 要求 |
|---|---|
| 单位 | 1 单位 = 1 米；猫高 0.35m，狗高 0.5m，房间 4m × 4m × 2.6m |
| 面数 | 宠物 ≤ 6k 三角面；单件家具 ≤ 2k；房间整体 ≤ 20k |
| 贴图 | 单张 ≤ 1024×1024，宠物一张图集；格式 PNG，导入时压 ASTC/ETC2 |
| 骨骼 | 统一前缀 `B_`；必需骨骼：根、脊椎、头、双耳、四足、尾 |
| 动画 | `idle / walk / eat / play / sleep / rub / sick`，每段 24–48 帧 @30fps，循环动画首尾帧对齐 |
| 命名 | `cat_idle.fbx`、`dog_eat.fbx`；场景 `room_day.fbx` |
| 导出 | FBX 7.4，烘焙动画，不带灯光/相机；材质用 Standard PBR |
| 交付 | 每品种一份 `.fbx` + 一份贴图 + 一段 3 秒预览视频 |

## 2. 性能预算（G-21）

| 指标 | 上限 | 说明 |
|---|---|---|
| 首包 | 4MB | 只放 Home 房间 + 宠物 idle + UI |
| 分包总量 | 20MB | 其余动画、家具、语音 |
| 同屏三角面 | 8 万 | 房间 + 宠物 + 家具 |
| drawcall | ≤ 80 | 靠图集与材质合并 |
| 同屏光源 | ≤ 2 | 主光 + 环境光 |
| 低端机帧率 | ≥ 30fps | 目标机型：骁龙 6 系 / 3GB 内存安卓 |
| 内存峰值 | ≤ 250MB | 3D 贴图与音频为主 |

## 3. 镜头脚本（G-22）

| 场景 | 机位 | 触发 | 时长 |
|---|---|---|---|
| 打开游戏 | `idle`：低机位平视，距宠物 2.2m | 进入 Home | 常驻 |
| 回家迎接 | `welcome`：宠物从房间深处跑向镜头，机位前推 0.4m | 距上次登录 > 30 分钟 | 2.5s |
| 抱抱 / 摸头 | `closeup`：距宠物 0.9m，轻微俯角 | 点击动作按钮 | 1.8s |
| 投喂 | `idle` + 食物特写插入 | 投喂成功 | 1.2s |
| 玩耍 | 跟随宠物横向摇移 | 拖拽逗猫棒 | 持续 |
| 生病 | `idle`，亮度降 15%，宠物蜷缩 | sick = true | 常驻 |
| 重逢 | `welcome` + 缓慢推近 + 停顿 | 距上次登录 > 3 天 | 4s |

## 4. 验收（G-24）

- [ ] 面数、贴图尺寸、命名逐项核对（用工具脚本扫 `assets/models3d`）
- [ ] 七个动画在引擎里播放无穿插、无滑步

## 已拍板（2026-11-18）

用户确认：**宠物本体用 3D**（模型 + 骨骼动画）。因此：

| 项 | 结论 |
|---|---|
| 宠物本体 | 3D 模型 + 7 段骨骼动画（idle / walk / eat / play / sleep / rub / sick） |
| 资料库的 2D 切图规范 | 降级为 **UI 图标 / 立绘 / 分享卡** 使用，不用于宠物本体 |
| sick 动作 | 复用 `sleep` 姿态 + 抖动与滤镜，不单独做动画（省一段骨骼动画） |
| 动作数 | 3D 侧 7 段；2D 侧仍按资料库 6 段（UI 预览与分享卡用） |
| 设计令牌 | 以 `design/tokens.json` 为准（奶油白 #FAF7F0 / 橙 #ED8A4C / 近黑 #1F1D1A），资料库第四节的紫灰模板**未采用** |
| 语音 | 以 `voice/index.json` 为准（400 条，voiceId = sha1 前 8 位） |

### 为什么令牌没用资料库那套

资料库第四节给的是通用模板色（bg #f5f6f8、brand #5b4ef0 紫、catPrimary #f5a623），而我们已经评审通过并出了 14 页原型的是「奶油白 + 橙 + 近黑」。两套同时存在会让 Cocos 里的按钮和原型对不上，所以：**语料 / 语音 / 切图命名以资料库为准，颜色与圆角以已评审的 tokens 为准**。要换色只改 `design/tokens.json` 一行。
